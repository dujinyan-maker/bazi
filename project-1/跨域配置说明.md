# 跨域配置说明

## 配置说明

已为项目添加了全局跨域配置，解决前端跨域访问问题。

### 配置文件位置

跨域配置在 `application.yml` 中：

```yaml
# 跨域配置
cors:
  # 允许的跨域源（多个用逗号分隔，例如：http://localhost:3000,http://localhost:8080）
  # 如果为空或注释掉，则允许所有源（开发环境使用，生产环境建议指定具体域名）
  allowed-origins: 
  # 是否允许携带凭证（Cookie、Authorization等）
  allow-credentials: true
  # 预检请求的缓存时间（秒），默认1小时
  max-age: 3600
```

### 配置选项说明

1. **allowed-origins**（允许的跨域源）
   - 如果为空：允许所有源访问（开发环境）
   - 如果配置：指定允许的前端地址，多个用逗号分隔
   - 示例：`http://localhost:3000,http://localhost:8080,https://yourdomain.com`

2. **allow-credentials**（是否允许携带凭证）
   - `true`：允许携带 Cookie、Authorization 等凭证信息
   - `false`：不允许携带凭证
   - **注意**：当 `allowed-origins` 为空（允许所有源）时，此选项会自动设置为 `false`（CORS 规范限制）

3. **max-age**（预检请求缓存时间）
   - 单位：秒
   - 默认：3600 秒（1小时）
   - 浏览器会缓存 OPTIONS 预检请求的结果，减少重复请求

## 使用场景

### 场景 1：开发环境（允许所有源）

**配置**：
```yaml
cors:
  allowed-origins:  # 留空
  allow-credentials: true
```

**说明**：
- 允许所有前端地址访问
- 不能携带凭证（CORS 规范限制）
- 适合本地开发测试

### 场景 2：生产环境（指定具体域名）

**配置**：
```yaml
cors:
  allowed-origins: https://yourdomain.com,https://www.yourdomain.com
  allow-credentials: true
```

**说明**：
- 只允许指定的域名访问
- 可以携带凭证（Cookie、Authorization 等）
- 更安全，适合生产环境

### 场景 3：多环境配置

**开发环境**（`application-dev.yml`）：
```yaml
cors:
  allowed-origins: http://localhost:3000,http://localhost:8080
  allow-credentials: true
```

**生产环境**（`application-prod.yml`）：
```yaml
cors:
  allowed-origins: https://yourdomain.com
  allow-credentials: true
```

## 允许的 HTTP 方法

配置中已允许以下 HTTP 方法：
- GET
- POST
- PUT
- DELETE
- OPTIONS（预检请求）
- PATCH

## 允许的请求头

配置中允许所有请求头（`*`），包括：
- `Content-Type`
- `Authorization`
- `X-Requested-With`
- 其他自定义请求头

## 测试跨域配置

### 1. 使用浏览器开发者工具

打开浏览器开发者工具（F12），在 Network 标签中查看请求：
- 请求头中应该包含 `Origin`
- 响应头中应该包含 `Access-Control-Allow-Origin`
- 如果是预检请求（OPTIONS），应该返回 200 状态码

### 2. 使用 curl 测试

```bash
# 测试预检请求
curl -X OPTIONS http://localhost:8081/blessing/list \
  -H "Origin: http://localhost:3000" \
  -H "Access-Control-Request-Method: GET" \
  -v

# 测试实际请求
curl -X GET http://localhost:8081/blessing/list \
  -H "Origin: http://localhost:3000" \
  -v
```

### 3. 前端测试代码

```javascript
// 测试 GET 请求
fetch('http://localhost:8081/blessing/list', {
  method: 'GET',
  headers: {
    'Content-Type': 'application/json'
  }
})
.then(response => response.json())
.then(data => console.log(data))
.catch(error => console.error('Error:', error));

// 测试 POST 请求（需要 Authorization）
fetch('http://localhost:8081/blessing/send', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer your-token-here'
  },
  body: JSON.stringify({
    content: '测试祝福语'
  })
})
.then(response => response.json())
.then(data => console.log(data))
.catch(error => console.error('Error:', error));
```

## 常见问题

### 1. 仍然出现跨域错误

**可能原因**：
- 配置未生效，需要重启应用
- 前端请求的 Origin 不在允许列表中
- 请求头中包含不允许的字段

**解决方法**：
- 检查 `application.yml` 配置是否正确
- 重启 Spring Boot 应用
- 检查浏览器控制台的错误信息

### 2. 预检请求失败

**可能原因**：
- OPTIONS 请求被拦截
- 请求头不匹配

**解决方法**：
- 确保配置中包含了 `OPTIONS` 方法
- 检查 `allowed-headers` 配置

### 3. 无法携带 Cookie

**可能原因**：
- `allow-credentials` 设置为 `false`
- `allowed-origins` 使用了 `*`（不能同时使用）

**解决方法**：
- 配置具体的 `allowed-origins`（不能为空或 `*`）
- 设置 `allow-credentials: true`
- 前端请求时设置 `credentials: 'include'`

## 安全建议

1. **生产环境**：务必配置具体的 `allowed-origins`，不要使用 `*`
2. **HTTPS**：生产环境使用 HTTPS
3. **最小权限**：只允许必要的 HTTP 方法和请求头
4. **定期审查**：定期检查跨域配置，确保安全性
